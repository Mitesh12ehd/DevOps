Function arguments:

        display_details() {
            echo "Name: $1"
            echo "Age: $2"
            echo "City: $3"
        }
        display_details "Mitesh" 22 Amd

    - for argument beyond 9, use curly braces
        echo "${10}"

    - script can also have positional arguments,
      if we pass parameter to script, it not directly available to function 
      we must pass to function, if we want to use it

    - passing indexed array:
        install_packages() {
            local packages=("$@")

            for package in "${packages[@]}"; do
                echo "Installing $package"
            done
        }
        my_packages=("git" "docker" "nginx" "kubectl")
        install_packages "${my_packages[@]}"

        - here we are expanding array into separate argument

    - passing associative array:
        - we can't pass whole array
        - pass key and value separately

Pass by reference:
    - normally bash passes variable as pass by value
    - but there is one way to implement pass by reference similar concept.

    Nameref variables using local -n or declare -n:
        - A nameref is a variable that refers to another variable by its name.
        - syntax: local -n reference_name=variable_name     

    ex.
        update_value() {
            local -n ref_var=$1
            ref_var="Updated"
        }
        APP_NAME="Threads"
        update_value APP_NAME
        echo "$APP_NAME"

        o/p: Updated

    Rule: 
        - here we have passed APP_NAME without $
        - as we have passed only variable name, not value

    Passing indexed arrays by reference:
        add_package() {
            local -n packages=$1
            packages+=("$2")
        }
        DOCKER_PACKAGES=("docker" "containerd")\
        add_package DOCKER_PACKAGES "docker-compose"
        echo "${DOCKER_PACKAGES[@]}"

    Passing associative arrays by reference:
        update_config() {
            local -n config=$1
            config[environment]="production"
            config[port]="8080"
        }
        declare -A APP_CONFIG=(
            [environment]="development"
            [port]="3000"
        )
        update_config APP_CONFIG
        echo "Environment: ${APP_CONFIG[environment]}"
        echo "Port: ${APP_CONFIG[port]}"

Function return values:

    Returning status using 'return':
        - Bash provides the return keyword to exit a function and set its exit status.
        - syntax: return STATUS_CODE

        ex. 
        check_application() {
            echo "Checking application..."
            return 0
        }
        check_application

        # return without status 
        # it return exit status of last command executed
        check_application() {
            echo "Checking application..."
            return
        }

    Capturing function status using $?
        check_service() {
            return 1
        }
        check_service
        echo "Exit status: $?"

    How to return values from function:
        - by print statement like echo or printf
        - using command substitution

        - ex.
        get_image_tag() {
            echo "threads:v1.0.0"
        }
        IMAGE_TAG=$(get_image_tag)
        echo "Docker image: $IMAGE_TAG"

Function libraries:
    - A function library is a separate Bash file containing reusable functions that can be imported into other scripts.
    
    - assume below structure
        devops-project/
        │
        ├── scripts/
        │   ├── deploy.sh
        │   ├── backup.sh
        │   └── monitor.sh
        │
        └── libraries/
            ├── logging.sh
            ├── validation.sh
            └── docker.sh
    
    logging.sh
        #!/bin/bash
        log_info() {
            echo "[INFO] $*"
        }

        log_error() {
            echo "[ERROR] $*" >&2
        }

        log_warning() {
            echo "[WARNING] $*"
        }
    
    validation.sh   
        #!/bin/bash
        check_command() {
            local command_name="$1"
            if command -v "$command_name" > /dev/null 2>&1; then
                return 0
            else
                return 1
            fi
        }
    
    deployment.sh
        source "../libraries/logging.sh"
        source "../libraries/validation.sh"

        log_info "Starting deployment"

        if check_command docker; then
            log_info "Docker is installed"
        else
            log_error "Docker is not installed"
            exit 1
        fi

        log_info "Deployment preparation completed"

Sourcing files:
    - executing other file in current shell environment, rather than creating separate process
    - way to source file 
        source filename
        . filename

    - ex.
        project:
            - main.sh
            lib:
                - function.sh

        main.sh
            source ./lib/functions.sh
            greet
            result=$(calculate 10 20)
            echo "Result: $result"

    path:
        - when we give relative path it works from that directory only.
        - either we can provide absolute path 
        
        reliable approach:
            SCRIPT_DIR="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)"
            source "$SCRIPT_DIR/lib/functions.sh"

            - ${BASH_SOURCE[0]} identifies the current script filepath.
            - dirname extracts it directory
            - cd and pwd finds absolute path 
            - library sourced using absolute path

Function overriding:

    - ex. 
        greet() {
            echo "Hello"
        }
        greet
        greet() {
            echo "Hello Mitesh"
        }
        greets

        o/p: Hello
             Hello Mitesh
        
    - Function overriding through libraries:
        - it is much important while sourcing the file
        - order of source matters
        - recently source code get priority
    
    - Function override linux command:
        - bash function takes priority over linux command
        - ls() {
                echo "My custom ls function"
            }
            ls
        - o/p: My custom ls function

How to execute linux command over the function?
    - using command 
        command ls
    - it bypass all function definition

    - Remove the function:
        unset -f ls
