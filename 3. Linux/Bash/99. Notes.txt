Input, Output and error:
	- every commands three communication channels:
		- standard input (stdin) 0 : recieve input
		- standard oputput (stdout) 1 : display normal output
		- standard error (stderr) 2 : display error message
		
	Standard input:
		- By default, stdin is connected to your terminal (keyboard).
		- read name:
			- it wait for input 
		- cat without argument read from stdin
			- Whatever you type is displayed back because cat sends the received input to stdout.
		- cat: taking input from file contect
			cat < input.txt
	
	Standard output:
		- Standard output is where a command sends its normal output.
		- by default it is connected to terminal, it print on terminal
		- You can redirect stdout to a file:
			echo "Hello World" > output.txt
			echo "Hello World" >> output.txt	# append
		
		- redirecting implicitly doing, here 1 is stdout code
			echo "Hello World" 1> output.txt
			echo "Hello World" 1>> output.txt	# append
			
	Standard error:
		- Standard error is where a command sends error messages.
		- By default, stderr is also connected to your terminal. it print error on terminal
			
		- redirect error:	
			ls /abc123 2> error.txt
			ls /abc123 2>> error.txt # append
			
	ping google.com > /dev/null 2>&1:
		- redirects both standard output and standard error to /dev/null, so nothing is displayed in the terminal.
		
		2>&1
			- redirect stderr(2) to wherever stdout(1) is currently pointing
			- ping google.com > means ping google.com 1>
			- so stdout is pointing to /dev/null, so error will also go there.

exit:
	- command to terminate current shell or script and optionally return exit status
	- syntax: exit [status]
	
	Example:
		if [ -f "config.txt" ]; then
		    echo "Configuration file found"
		    exit 0
		else
		    echo "Configuration file not found"
		    exit 1
		fi

set -e 
	– Exit on command failure:
	- if any command fails, script exits

set -o pipefail
	- command1 | command2 | command3
	- pipeline's exit status is normally the status of command3.
	- what if command 1 fails and and command 3 succeeds, pipeline report success
	- To catch failures in pipelines:
		set -o pipefail

null:
	- : is called null command 
	- it does nothing and always return 0 (success)
	- used in scripting for 
		- creating empty command blocks
		- writing infinite loops
